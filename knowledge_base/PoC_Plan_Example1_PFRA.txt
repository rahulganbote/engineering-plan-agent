## PoC Hypothesis
poc_hypothesis: |
  We believe that LangChain + GPT-4o + Pinecone can generate a cross-correlation
  insight between structured financial metrics and unstructured market report text
  that is accurate enough (>= 80% Domain Expert approval rate across 5 test scenarios)
  to replace manual analysis for the PFRA use case, validating RISK-01 from the BRD
  (LLM narrative depth and accuracy sufficient for executive decision-making).

## Scope In
scope_in:
  - Single predefined test question: Did sustainability sentiment shifts correlate with Product Line Alpha Q3 margin decline?
  - Two data sources only: Business Metrics DB (structured JSON) + 50 sample PDFs in Pinecone
  - Single LangChain synthesis chain with citation extraction
  - Markdown text output only — one paragraph with source citations

## Scope Out
scope_out:
  - Full ETL pipeline — use hardcoded sample data only
  - Email delivery automation
  - User interface or dashboards
  - Handling more than 2 data sources
  - Ad-hoc query support — predefined question only
  - Production infrastructure or authentication
  - PDF report generation
  - Error handling beyond basic logging

## Duration
duration_weeks: 2

## Success Criteria
success_criteria:
  - metric: Domain Expert approval rate
    target_value: ">= 4 of 5 predefined test scenarios rated 'accurate and useful'"
    measurement_method: Domain Expert reviews 5 generated outputs against known historical answers and scores each pass or fail

  - metric: End-to-end runtime
    target_value: "< 15 minutes"
    measurement_method: Timed over 3 consecutive runs on staging environment with real Pinecone + OpenAI calls

  - metric: Citation completeness
    target_value: Every factual claim contains a (Source: chunk_id) reference
    measurement_method: Automated regex check counting claims without citation pattern

## Team
team_size: 2

## Risk If PoC Fails
risk_if_poc_fails: |
  If the LLM cannot generate specific, traceable cross-correlation insights with >= 80%
  Domain Expert approval, the AI-native approach is not viable for PFRA.
  Fallback: template-based report where analyst fills narrative sections manually, with AI
  only handling data aggregation and table formatting. This reduces system value by ~60%
  and eliminates the primary business case (replacing 5-day manual cycle with automation).
  Business impact: project may be deprioritized or reframed as a data dashboard rather
  than an intelligent reporting agent.

## Go / No-Go Decision Criteria
go_nogo_criteria:
  go:    "4 or more of 5 test scenarios rated accurate AND runtime < 15 min AND all claims contain source citations"
  no_go: "Fewer than 3 of 5 scenarios accurate OR hallucinations (uncited claims) detected in more than 2 outputs"
  pivot: "3 to 4 of 5 scenarios accurate but insights lack specificity — pivot: tighten prompt constraints and re-test with pre-filled context template rather than pure RAG retrieval"
