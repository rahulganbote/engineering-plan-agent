## PoC Hypothesis

  We believe that per-tenant Kubernetes namespaces + per-tenant S3 bucket policies +
  per-tenant Elasticsearch shards + JWT token validation at API Gateway will prevent
  any cross-tenant data access (including under adversarial API manipulation and token
  forgery), validating RISK-01 from the BRD (tenant isolation catastrophic liability risk).
  If proved, the architecture is safe to load with real attorney-client privileged data.

## Scope In
scope_in:
  - Per-tenant Kubernetes namespace - 3 simulated tenants
  - API Gateway with JWT validation and tenant token extraction
  - Per-tenant S3 bucket with bucket policies enforcing isolation
  - Per-tenant Elasticsearch shard with index-level access control
  - Automated adversarial test suite - 500 cross-tenant API call scenarios
  - BYOK simulation - 3 separate KMS keys, one per simulated tenant

  - SOC 2 evidence collection
