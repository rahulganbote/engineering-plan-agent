## Pattern Selection
pattern: Secure batch analytics pipeline
pattern_justification: |
  eDiscovery scoring is large-scale and batch-oriented with defensibility requirements; real-time APIs were rejected because reviewer queues are generated in matter batches. Team size is assumed to be 5-8 engineers, which is enough for clear component ownership without creating unnecessary platform overhead. The primary NFR driver is Score 1 million documents in <= 6 hours. The architecture respects compliance constraints for Attorney-client privilege, legal hold chain-of-custody, SOC 2, GDPR where applicable.

## Components
components:
  - name: Matter Ingestion Adapter
    responsibility: Imports document metadata and text by matter.
    technology: Python + Relativity SDK
    interfaces: [REST, batch files]
  - name: Privilege Scoring Pipeline
    responsibility: Scores documents using rules and ML features.
    technology: Spark + scikit-learn
    interfaces: [Batch jobs, Parquet]
  - name: Review Batch API
    responsibility: Creates prioritized batches and exports decisions.
    technology: FastAPI + PostgreSQL
    interfaces: [REST]
  - name: Defensibility Log Store
    responsibility: Stores model versions, features, thresholds, and actions.
    technology: Immutable S3 + PostgreSQL
    interfaces: [Object API, SQL]
