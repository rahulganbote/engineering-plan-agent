## Pattern Selection
pattern: Event-driven workflow orchestration
pattern_justification: |
  Claim intake has long-running document and assignment steps; event orchestration handles retries and surge. A synchronous three-tier app was rejected because uploads and OCR would block user flows. Team size is assumed to be 5-8 engineers, which is enough for clear component ownership without creating unnecessary platform overhead. The primary NFR driver is Submit FNOL and receive triage result in <= 5 seconds P95 excluding upload time. The architecture respects compliance constraints for NAIC model audit expectations, state claims handling rules, SOC 2.

## Components
components:
  - name: FNOL API
    responsibility: Captures claim intake requests and upload metadata.
    technology: Node.js NestJS
    interfaces: [REST, presigned URLs]
  - name: Document Intelligence Worker
    responsibility: Extracts text and classifies claim documents.
    technology: AWS Textract + Python
    interfaces: [S3 events, queue]
  - name: Triage Rules Service
    responsibility: Combines policy, severity, and routing rules.
    technology: Drools + Java Spring Boot
    interfaces: [REST, rules repository]
  - name: Claims Adapter
    responsibility: Creates claim records and assignments in the core system.
    technology: MuleSoft API
    interfaces: [REST/SOAP]
