## Pattern Selection
pattern: Workflow and reporting platform
pattern_justification: |
  Readiness tracking is workflow-heavy with reporting and audit requirements; a data lake-only approach was rejected because users need controlled state transitions and e-signature evidence. Team size is assumed to be 5-8 engineers, which is enough for clear component ownership without creating unnecessary platform overhead. The primary NFR driver is Dashboard loads readiness for 5,000 documents in <= 3 seconds P95. The architecture respects compliance constraints for 21 CFR Part 11, GxP validation, ICH eCTD conventions.

## Data Flow

  - "3. Processing components enrich, score, or route the request using Submission plans, document metadata, QC status, approval evidence, market-specific dependencies."
  - "4. Workflow/API layer presents results to Regulatory affairs managers, publishing specialists, quality reviewers and records audit evidence."
