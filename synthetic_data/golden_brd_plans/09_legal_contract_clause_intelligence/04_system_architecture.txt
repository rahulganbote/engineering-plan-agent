## Pattern Selection
pattern: RAG-augmented document intelligence
pattern_justification: |
  Clause review requires grounded retrieval and cited recommendations; rules-only matching was rejected because playbooks contain nuanced fallback language. Team size is assumed to be 5-8 engineers, which is enough for clear component ownership without creating unnecessary platform overhead. The primary NFR driver is Analyze a 60-page contract in <= 3 minutes P95. The architecture respects compliance constraints for Attorney-client privilege controls, SOC 2, GDPR for EU contracts.

## Components
components:
  - name: Document Parser
    responsibility: Extracts text, sections, and clause boundaries.
    technology: Azure AI Document Intelligence + Python
    interfaces: [REST, queue]
  - name: Clause Classifier
    responsibility: Labels clauses and confidence scores.
    technology: Python FastAPI + transformer classifier
    interfaces: [REST]
  - name: Playbook RAG Service
    responsibility: Retrieves approved guidance and drafts review notes.
    technology: LangChain + Pinecone + OpenAI enterprise endpoint
    interfaces: [REST, vector API]
  - name: Legal Review Workbench
    responsibility: Presents findings and captures attorney decisions.
    technology: React + FastAPI
    interfaces: [REST]

## Data Flow
data_flow:
  - "1. User or upstream system submits data for Contract Clause Intelligence and Playbook Review."
  - "2. Entry service validates identity, schema, and consent or policy constraints."
  - "3. Processing components enrich, score, or route the request using Contracts, clause library, legal playbooks, fallback terms, opportunity metadata, reviewer notes."
  - "4. Workflow/API layer presents results to Commercial counsel, contract managers, sales operations and records audit evidence."
  - "5. Failure path: integration failures are queued, retried, and shown with actionable status."
